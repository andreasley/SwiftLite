# Question: How to implement observability in @Model?

- Custom setter/getter for stored properties needs to be created by @Model to be able to differentiate between value updates from the user (need to be marked as "pending/unsaved" and should notifiy observers) and value updates from sync (should notify observers)

- Duplicating the functionality of `@Observable` in `@Model` would likely be possible but fairly complex. Also, `@Observable` might be optimized in the future. It is therefore preferable to just use `@Observable` (if possible).

- There are use-cases in which the model doesn't need to be observable, so making that configurable is a good idea.

- Having both `@Model` and `@Observable` on the same class is not possible, as they generate conflicting getters/setters for properties (which can't be prevented, because they run on the same "level")

**Decisions:**

Store the mutable variables in a nested backing class (referenced by a `private` property) and let the getters/setters (generated by `@Model`) just forward to the backing class' properties. The backing class can be marked `@Observable` –  notifications just bubble up and observation on the properties of the Model class works fine.
